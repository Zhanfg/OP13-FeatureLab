# v0.4.0 preflash audit

The artifact passed archive, Shell, JavaScript, JSON and XML syntax checks, but syntax validity did not establish safe runtime behavior.

## Release blockers

### P0-01 — Credential/privacy window-policy loss

The generated `sys_wms_split_app_ps.xml` reduced a large original policy database to a small replacement and removed rules associated with credential confirmation, privacy password, Keyguard, fingerprint enrollment and security-center flows.

Required resolution: generate from the device baseline and preserve all unrelated and protected records. Broad window unlock must be an isolated Lab profile.

### P0-02 — Recovery bypass by static properties

Root-level `system.prop` would continue loading even when script-based recovery mode skipped mounts and services.

Required resolution: replace unconditional properties with feature-scoped staged application controlled by the same recovery state.

### P0-03 — Incorrect KernelSU lifecycle stage

Runtime bind mounts were attempted in `post-fs-data`, before the module overlay lifecycle was guaranteed complete.

Required resolution: use the correct `post-mount`/`late-load` integration and verify behavior on the target manager version.

### P0-04 — Incomplete mount rollback

A boot-time mount failure could leave a partially applied configuration.

Required resolution: preflight every operation and use an all-or-nothing transaction with verified rollback.

### P0-05 — Inadequate mount ownership

Ownership was recorded by path only.

Required resolution: record mount ID, parent ID, root/device, target and creation order; unmount only when the current top layer still matches.

### P0-06 — WebUI mock-success fallback

When the manager API could not be imported, the WebUI substituted mock status and successful actions.

Required resolution: release builds must enter a read-only failure state and expose the actual API/command error.

### P0-07 — Unsafe defaults

Touch experiments and extreme brightness/protection-removal changes were enabled in the default path.

Required resolution: Stable defaults disable all such profiles. Lab retains them as individually reversible, disabled-by-default experiments.

### P0-08 — Camera/face boundary violation

Face enrollment/detection and image-related declarations remained in the generated feature pool.

Required resolution: protect camera, face and biometric-adjacent semantics and keep them outside the main module.

### P0-09 — Proprietary payload distribution

The artifact embedded complete or near-complete vendor files without an explicit redistribution license.

Required resolution: public source contains only original logic and patch specifications; payload generation occurs locally on the user's device.

## Additional high-priority findings

- immutable-file manifest did not cover every core script and WebUI file;
- dynamic WebUI mounting did not prove it affected the Android global namespace;
- static bind mounts were not remounted read-only;
- privileged permissions were expanded without feature-scoped review;
- old module/app states were not restored precisely;
- charging control lacked ownership and competing-controller coordination;
- claimed WebUI feature state was not one-to-one with unconditional properties;
- safety scan checked paths but not protected XML semantics.

## Closure criteria

This audit closes only when each blocker has:

1. an implemented fix;
2. automated regression coverage;
3. a real-device test result on a declared supported build;
4. a link to the commit and sanitized evidence;
5. release-gate status updated in `docs/STATUS.md`.
