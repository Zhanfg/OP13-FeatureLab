# Media decoder evidence protocol\n\nThis protocol closes the gap between configuration presence and actual PCM output.\n\n## Evidence ladder\n\n1. declared — codec/VINTF configuration contains the expected identity;\n2. registered — Android runtime exposes the service/component;\n3. process context — process, executable and SELinux domain are correct;\n4. component creation — MediaCodec creation succeeds for the exact component;\n5. PCM output — decoding produces non-zero audio/raw output with input and PCM hashes.\n\nA lower layer never proves a higher layer.\n\n## Public evidence\n\n`schemas/media-decoder-evidence.schema.json` defines the provider-neutral report.\n`tools/media/validate-decoder-evidence.py` enforces unique MIME rows, successful discovery and creation, positive PCM output, SHA-256 bindings and freshness.\n\n## Inert reference trees\n\n`tools/media/audit-inert-provider-root.py` makes historical provider trees fail closed if they still contain process/service control, mount/property/SELinux mutation, direct vendor binary launch, active init/VINTF overlays, active system.prop or active sepolicy.rule.\n\n## Architecture conclusion\n\nCurrent Android VINTF/vendor-init guidance and current public SM8750/OnePlus Dolby integrations all use coordinated init, VINTF, SELinux, service binaries and dependency families. FeatureLab therefore does not treat a late root-module overlay or a process running in a module/root domain as equivalent to ROM-integrated vendor service registration.\n\nBuild Verified != Runtime/Device Verified\n
